# 金鸽杯会员账户测试环境

## 隔离范围

这是正式网站的完整源码克隆，基线见根目录 `STAGING_BASELINE.md`。会员功能仅在本测试服务中启用。

- 正式 GitHub Pages、正式 Firebase、当前报名和本机财务均不变。
- 测试分支：`test/member-accounts`；已禁用该克隆的远程 push URL。
- 数据库：`sandbox/.data/members.sqlite`，不是浏览器 localStorage。
- 密码使用 bcrypt 哈希；服务端会话保存到 SQLite，浏览器只有 HttpOnly 会话 Cookie。
- 稳定会员ID负责报名归属；姓名、尾号不会授予编辑权限。
- 所有页面有明显的测试标识；测试支付邮箱为 `payments-test@example.invalid`，不要转真实款项。
- 默认只监听 `127.0.0.1`，拒绝其他 Host，内容安全策略禁止连接正式 Firebase。
- 不会在11月7日自动上线，必须活动结束后再次明确批准。

## 启动

需要 Node.js 24+。首次安装使用 `pnpm install`（在此目录内），已有依赖无需重装。

```powershell
node server.mjs
```

默认地址：`http://127.0.0.1:4187/`。

Windows也可以运行此目录的 `start-sandbox.ps1`，它会复用正在运行的测试服务，或隐藏启动一个后台进程；端口被其他服务占用时不会覆盖。

- `/`：正式主页克隆，右上角改为登录/个人账户。
- `/signup.html?venue=mrtc`：MRTC测试报名。
- `/signup.html?venue=nyta-east`：NYTA测试报名。
- 报名页现直接复用 `live-signup/` 中的正式模板（d4ee1a5），不是会员后台的自制接龙样式；仅替换启动数据接口、账户身份和管理员入口，保留正式版CSS、名单卡片、页签、确认/付款/退出弹窗与左下角语言滑块。测试MRTC同步24人，NYTA仍12人/每级4人。
- `/account.html`：个人主页。
- `/finance.html`：管理员工作台（必须真实服务端管理员会话）。

这是本机测试地址，手机不能直接使用手机自己的127.0.0.1访问。两个独立浏览器登录同一账户可验证跨会话同步。对外测试需要另设受保护的HTTPS测试服务，不要直接把该端口公开到互联网。

## 可测试流程

1. 匿名浏览主页、照片与报名名单；报名时登录/注册，默认记住30天并在使用时续期。
2. 同一账号在另一浏览器登录，原报名、付款、到场与套餐保持一致。
3. MRTC共享32总名额；NYTA每级4人、总12人，满员候补，补位寻找符合等级空位的人。
4. 报名不计到场、不扣次；模拟转账为待核实；管理员确认后才记实收或增加10次。
5. 管理员可更正待核实付款项目，但更正不会自动确认到账。
6. Nina授权Vivi后，两人实际到场各扣同一套餐1次，从10到8；收入仍350；分别各计1次到场。
7. 撤销Vivi的到场，返还Nina1次，并保留原扣次与撤销流水。
8. 不允许重复到场、负余额、无授权扣别人套餐；已使用套餐不能直接整笔退款，需先核对并撤销相关到场。
9. 旧报名只能发起关联申请，管理员独立核实后批准；不按同名或尾号自动认领。内置一条虚构旧报名示例。
10. 归档场次锁定报名，但不会把报名自动记为实际到场。
11. 管理员可导出测试账目；旧本机JSON只能预检，写入0条，不会自动导入真实财务。

